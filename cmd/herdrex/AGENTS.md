Flags and startup only; behavior belongs in `internal/bridge`. The CLI uses cobra. Because the bridge has no authentication, `--listen` stays limited to loopback and Tailscale addresses, and a LAN address needs `--lan`; `--ts` adds this machine's Tailscale addresses, while `--lan` selects local LAN addresses by interface default (`en0`) or repeated address/CIDR selectors, all on the configured port. Loopback and Tailscale callers are always admitted; a LAN caller needs `--allow` (CIDR or bare addresses), which admits only those networks over HTTP. `herdrex ssh` stores uploads on the remote host (`sshUploads`), since the pasted path must exist where the pane runs. `--add-host` shells out to `rex hosts`; it never edits Rex files itself. `rexBin` finds rex on PATH, else in Rex.app's install paths, and checks `rex version` because Homebrew's `rex` is another program. `--new` is `--start` at a fresh `/tmp/herdrex-XXXX/herdr.sock`, picked after `--daemon` re-executes so the child owns it, and removed with the server. `--start` and `test` start Herdr only through `pkg/herdr/cli.StartServer`, which refuses anything that could touch the user's Herdr. Cleanup removes sockets only after stopping the server this run started; never remove a socket on a failed start, it may be another server's. `--daemon` re-executes the binary with the same flags in a new session and waits on a pipe (`HERDREX_READY_FD`) until the child serves; the child unsets the variable and marks the descriptor close-on-exec, so a Herdr server it starts does not keep the pipe open. `herdrex ssh --herdr-socket`, `--start` and `--new` name or start a server on the remote host: `sshstart.go` runs a `sh` script in one SSH session that starts the server and treats the end of its stdin as the signal to stop it and remove its files, so a dropped connection cleans up too; it applies the same refusals as `StartServer` by path comparison. Every remote command goes through `util.RemoteCommand`, which quotes for the login shell and runs `sh -c`, and puts the usual install directories on PATH because a non-interactive SSH PATH lacks them. `herdrex ssh` parses its own flags with the definitions `flags` and `startFlags` give `herdrex` (parseSSHArgs pulls those out of the args and leaves the rest for ssh), so a flag added there reaches both; `run` is the one serving path for both. The SSH plumbing that knows nothing of Herdr (tunnels, `RemoteCommand`, `LockDir`, `TailWriter`) lives in `pkg/util`; `reachHerdr` only chooses the order and probes each tunnel. Address selection (`SelectLAN`, `Tailscale`, `ListenSelected`, `ListenAutoPort`) and the `--allow` list (`AllowList`) are in `pkg/util/net.go`. `--allow all` admits every address; `--allow-for` ends `--allow` after a duration (`AllowList.ExpireAfter`) while loopback and Tailscale callers stay admitted. `update` (alias `upgrade`, `update.go`) reads the install channel from the binary's path (`detectChannel`: a Cellar link is brew, `$GOBIN` or `$GOPATH/bin` is go) and runs that channel's own commands; it never downloads or replaces the binary itself, checks every command exists before running the first, and leaves a running herdrex alone. The `script` channel reruns `install.sh` into the binary's own directory; `install.sh` records the path it installed in `$XDG_STATE_HOME/herdrex/install-path`, which `detectChannel` compares with the running binary. A new channel is a case in `updateSteps` and `detectChannel`.
